# Architecture

## Block Diagram

```
                     +-------------------------------------------+
                     |         soc_peripheral_subsystem_top       |
                     |                                             |
   s_axi (AXI4-Lite) |   +----------------------------------+      |
  ------------------>|   |     axi4_lite_interconnect        |      |
   (from CPU / TB)   |   |  (address decode + response mux)  |      |
                     |   +---+---------+---------+---------+-+      |
                     |       |         |         |         |        |
                     |   +---v--+  +---v--+  +---v---+ +---v----+   |
                     |   | GPIO |  | UART |  | Timer | |  INTC  |   |
                     |   +---+--+  +---+--+  +---+---+ +---^----+   |
                     |       |         |          |        |        |
                     |   gpio_*    uart_tx/rx  (irq) irq   |        |
                     |                              +------+--------+
                     |                              periph_irq[2:0]  |
                     +----------------------------------|------------+
                                                          v
                                                       irq_out
                                                   (single line to CPU)
```

Every peripheral is a standalone AXI4-Lite slave (its own instance of
`axi4_lite_slave_fsm` plus a small register file); the interconnect is the
only module that knows about all four of them, and the top level just
wires interconnect <-> peripherals <-> top-level pins together.

## Why a Shared AXI4-Lite Slave FSM

Every peripheral needs identical AW/W/B and AR/R handshake logic — only the
register file behind it differs. Factoring that into
`axi4_lite_slave_fsm` (rtl/axi4_lite_slave_fsm.sv) means:
- The AXI protocol logic is written and reviewed once.
- Each peripheral (`gpio_axi4lite`, `uart_axi4lite`, `timer_axi4lite`,
  `intr_ctrl_axi4lite`) only implements a combinational read mux and a
  synchronous write `case` statement against its own offsets.
- Bugs in bus handling can't diverge between peripherals.

The FSM is intentionally simple: one outstanding write and one outstanding
read transaction at a time. That's the right trade-off for a handful of
low-throughput control/status peripherals — a high-bandwidth AXI4 (non-Lite)
slave would need to pipeline multiple outstanding transactions, which these
peripherals don't need.

## Interconnect

`axi4_lite_interconnect` decodes the top 20 bits of the address (4 KB
per-peripheral regions) to select GPIO, UART, Timer, or the interrupt
controller, and remembers which slave owns the currently in-flight write
and read transaction (independently — AXI4-Lite's write and read channels
are fully decoupled) until that transaction's response completes. This
keeps the interconnect correct even if, hypothetically, a master issued a
read and a write to different peripherals back-to-back without waiting for
the first to finish.

An access to an address that doesn't match any of the four regions gets a
clean `DECERR` (`BRESP`/`RRESP` = `2'b11`), generated by the interconnect
itself rather than routed to a peripheral — there's no real slave to wait
on, so it completes in the same cycle it's accepted rather than hanging
the bus waiting for a response that would never come.

See [`register_map.md`](register_map.md) for the exact address map and
per-peripheral register layout.

## Interrupt Controller Design

Rather than re-latching interrupts, `intr_ctrl_axi4lite` relies on each
peripheral's own sticky, software-cleared (`W1C`) `INT_STATUS` register.
The controller just ORs the already-latched peripheral IRQ lines together
(with a per-source software mask) into one line to the CPU, and exposes a
`MASKED_PENDING` register so an ISR can identify the source without
walking every peripheral's status register individually. This avoids
duplicating latch-and-clear logic in a fourth place.

## Timing / Synthesis Notes

- The whole design is single-clock, single-reset (`clk` / active-low
  `rstn`), synchronous throughout — no gated clocks or combinational
  feedback loops, which keeps static timing analysis straightforward.
- `constraints/soc_peripheral_subsystem.xdc` constrains `clk` at 100 MHz
  and false-paths the GPIO/UART pins and asynchronous reset, since those
  are slow, board-level I/O rather than paths that need to meet the
  system clock's setup/hold requirements.
- `uart_rx`'s `rx_line` input is passed through a 2-flop synchronizer
  before any logic uses it, since it's asynchronous to `clk`.
- `scripts/synth.tcl` runs Vivado out-of-context synthesis and emits
  utilization + timing-summary + worst-path reports under `reports/`
  (see the top-level README for how to run it).
